## Architectural Narrative

### Task

Polish all template references to use Serene branding, create comprehensive deployment documentation, add journal seed data for development, rewrite the README from scratch, verify CSS theme consistency, and create E2E Bowser QA workflows for full user flow validation.

### Architecture

Three-worker Cloudflare architecture (web edge router, app SPA, api backend) connected via service bindings. Terraform manages infrastructure provisioning. Neon PostgreSQL via Hyperdrive for database. All currently use "example-\*" naming convention from the React Starter Kit template.

### Selected Context

- Wrangler configs define worker names, service bindings, routes, and env vars per environment (dev, staging, preview, production)
- Terraform tfvars control `project_slug` which feeds into worker naming in infrastructure provisioning
- `.env.example` provides shared defaults for local development
- `db/seeds/users.ts` establishes the seed function pattern
- `db/scripts/seed.ts` is the seed runner entry point
- CSS themes in both apps already use matching calm oklch palettes

### Relationships

- Terraform `project_slug` feeds into Terraform stack module which creates workers named `{slug}-{web,app,api}`
- Wrangler `name` field must match what Terraform creates (or what you deploy manually)
- Service binding `service` values in web wrangler must match the `name` values in app/api wrangler configs
- Seed script imports and calls seed functions from `db/seeds/` directory

### External Context

N/A - no external dependencies needed.

### Implementation Notes

- Route patterns in wrangler use a domain placeholder since the actual deployment domain varies per user. Use `serene.example.com` as the placeholder (users replace with their domain).
- The DATABASE_URL port should be 5434 to match the Docker Compose config documented in CLAUDE.md (port 5434 avoids conflicts with other projects).
- Database name in connection strings should change from `example` to `serene`.
- Journal seed data must use `userId` from existing seeded users. Since IDs are auto-generated, the seed function must query for existing users first to get their IDs.
- CSS themes are already consistent -- just verify and note in the plan (no changes needed).

### Ambiguities

- Route domains: Using `serene.example.com` as placeholder since actual deployment domain is user-specific.
- Seed data user association: Will query first seeded user (alice@example.com) and assign all journal entries to that user for simplicity.

### Requirements

1. README.md fully rewritten -- zero references to "React Starter Kit", "kriasoft", sponsor badges, template content
2. Deployment guides exist in `docs/deployment/` with Serene-specific content
3. `terraform.tfvars.example` defaults to `project_slug = "serene"` in all 4 environment files
4. Wrangler configs use `serene-{web,app,api}` naming, `APP_NAME: "Serene"`, domain placeholders updated
5. `.env.example` uses `APP_NAME=Serene`, correct DATABASE_URL port (5434), database name `serene`
6. Seed data includes realistic journal entries across multiple moods, tags, dates
7. E2E Bowser YAML covers full user flow: landing -> journal -> analytics, edit/delete, responsive
8. CSS themes verified consistent between web and app

### Constraints

- No actual infrastructure changes (only config examples and docs)
- Seed data must follow existing pattern in `db/seeds/users.ts`
- Bowser YAML must follow format in `ai_review/user_stories/auth.yaml`
- All wrangler service binding names must be consistent across all 3 wrangler files

### Selected Approach

**Approach**: Sequential configuration rename + documentation creation + seed data + Bowser YAML
**Description**: Replace all template-era naming ("example-\*", "myapp", "Acme Co.") with Serene branding across config files, create two new deployment docs, rewrite README from scratch, add journal seed data that queries existing users for ID association, and create E2E Bowser YAML for full flow testing.
**Rationale**: This is a straightforward find-and-replace across config files plus documentation authoring. No architectural decisions -- just applying the project's identity to configuration and documentation that still uses template defaults.
**Trade-offs Accepted**: Route domain patterns use `serene.example.com` placeholder rather than a real domain. Journal seed entries are all assigned to the first seeded user rather than distributed across multiple users (simplifies the seed logic while still producing visible data).

## 11. Troubleshooting

**Workers not connecting via service bindings:**

- Verify worker names in `wrangler.jsonc` match deployed worker names exactly
- Service bindings are non-inheritable -- each environment needs its own `services` array
- Check Cloudflare dashboard > Workers & Pages for deployed worker names

**Hyperdrive connection errors:**

- Verify Hyperdrive IDs in `wrangler.jsonc` match Terraform outputs
- Check Neon database is accessible (not paused due to inactivity)
- Ensure `prepare: false` is set in Drizzle config (required for connection pooling)

**AI vibe check not working:**

- Verify `ANTHROPIC_API_KEY` secret is set: `bun wrangler secret list --config apps/api/wrangler.jsonc`
- Check API worker logs for Anthropic API errors
- Verify KV namespace binding `AI_RATE_LIMIT` is configured

**Build failures:**

- Run `bun install --force` to rebuild native binaries (rollup, workerd)
- Ensure email templates build first: `bun email:build` before `bun api:build`

**Auth not working after deploy:**

- Verify `BETTER_AUTH_SECRET` is identical across all environments where sessions should be shared
- Check `APP_ORIGIN` matches the actual URL users access
- Verify `ALLOWED_ORIGINS` includes the correct domain for CORS

// apps/api/wrangler.jsonc (simplified)
